# CSP11 REL-GOV-3 Repository Identity and Provenance Contract

## Purpose

REL-GOV-3 binds a governed release candidate to an exact Git repository state.

The provenance layer must answer:

```
Which repository?
Which HEAD commit?
Which Git tree?
Which branch or detached state?
Which checkpoint tags point at HEAD?
Is the governed working tree clean?
Does the observed state match the expected release source?
```

## Authoritative Git observations

REL-GOV-3 derives evidence from Git commands executed against the candidate checkout.

Required observations:

```
repository
remoteUrl
branch
headSha
treeSha
tagsAtHead
changes
clean
```

The repository field is normalized to:

```
owner/repository
```

For CSP11 the expected repository is:

```
thecrimsonengineer/exam_platform
```

## Git commands

The implementation may use read-only Git commands including:

```
git rev-parse --show-toplevel
git remote get-url origin
git rev-parse HEAD
git rev-parse HEAD^{tree}
git symbolic-ref --short -q HEAD
git tag --points-at HEAD
git status --porcelain=v1 --untracked-files=all
```

REL-GOV-3 must not mutate Git history.

## Repository normalization

Supported remote shapes include:

```
https://github.com/owner/repository.git
https://github.com/owner/repository
git@github.com:owner/repository.git
ssh://git@github.com/owner/repository.git
```

They normalize to:

```
owner/repository
```

Malformed or unresolvable remote identities are blocking.

## SHA identity

HEAD and tree identities must be lowercase 40-character hexadecimal Git SHA-1 object identifiers.

REL-GOV records both because:

```
commit SHA = commit object identity
tree SHA   = exact repository file-tree identity
```

A commit mismatch or tree mismatch is blocking when an expected value is supplied.

## Clean-tree policy

REL-GOV uses:

```
git status --porcelain=v1 --untracked-files=all
```

Any returned governed change makes the candidate dirty.

Examples:

```
tracked modification   -> BLOCK
tracked deletion       -> BLOCK
staged change          -> BLOCK
untracked file         -> BLOCK
rename                 -> BLOCK
conflict               -> BLOCK
```

Git-ignored generated files are not returned by this command and therefore do not create false dirty-state failures.

## Detached HEAD

Detached HEAD is not silently accepted.

Default:

```
detached HEAD -> BLOCK
```

A detached checkout may pass only when all of the following are true:

```
allowDetachedHead = true
expectedCommitSha is supplied
observed HEAD equals expectedCommitSha
no expected branch is required
all other provenance checks pass
```

This supports exact-SHA CI checkouts without weakening source identity.

## Expected-source policy

A candidate provenance policy may require:

```
expectedRepository
expectedBranch
expectedCommitSha
expectedTreeSha
expectedTag
allowDetachedHead
requireClean
```

The policy returns explicit blocking failure IDs rather than a vague Boolean alone.

Initial failure IDs:

```
RGP001_REPOSITORY_MISMATCH
RGP002_DIRTY_WORKTREE
RGP003_BRANCH_MISMATCH
RGP004_COMMIT_MISMATCH
RGP005_TREE_MISMATCH
RGP006_EXPECTED_TAG_MISSING
RGP007_DETACHED_HEAD_NOT_ALLOWED
RGP008_DETACHED_HEAD_REQUIRES_EXPECTED_COMMIT
RGP009_EXPECTED_BRANCH_UNAVAILABLE
```

## Evidence determinism

Machine-local checkout paths are not part of the canonical provenance identity.

Tags are sorted.

Changes are emitted in Git status order because that order is deterministic for a stable checkout.

No current timestamp is generated by the provenance inspector.

## Relationship to REL-GOV-2

REL-GOV-2 established the manifest source fields:

```
repository
branch
commitSha
treeSha
clean
```

REL-GOV-3 provides the repository-derived evidence that will later populate and validate those fields.

REL-GOV-3 does not yet make the final release-admission decision. REL-GOV-4 owns admission.
