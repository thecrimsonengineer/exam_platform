MANDATORY CONTROLS
==================

1. TOKEN-AWARE MATCHING
Do not use unsafe raw substring matching for controlled signals.

Signal phrases must be matched using token-aware logic so that a signal
cannot match merely because its characters occur inside an unrelated word.

Preserve case-insensitive matching and existing normalization behavior.

2. SIGNAL CLASSIFICATION
Every controlled signal must have an explicit classification that can be
used by the scoring engine.

Do not treat all signals as equivalent.

Use a deterministic machine-readable representation.

3. SPECIFICITY WEIGHTING
Generic signals must contribute less evidence than distinctive,
competency-specific signals.

Do not allow generic high-frequency terms such as:

exposure
fire prevention
hazardous materials
training programs
management of change
risk analysis
statistics
forces
stresses

to dominate mappings merely because they occur frequently.

Weights must be deterministic and documented in code.

4. SIGNAL INDEPENDENCE
Multiple occurrences of the same conceptual evidence must not be treated
as independent signals.

Independence must operate on controlled signal identity/classification,
not simply phrase count.

5. PHRASE HIERARCHY COLLAPSE
Where a specific phrase and a broader parent phrase both match the same
evidence, collapse the redundant parent evidence.

Examples include:

"failure modes and effects analysis" versus "fmea"

and other parent/child or alias relationships that exist in the taxonomy.

Do not double-count equivalent evidence.

6. NEGATIVE-CONTEXT CHECK
Implement deterministic negative-context handling.

A signal appearing in a clearly negative, exclusionary, unrelated, or
non-topical context must not automatically create positive competency
evidence.

Do not use unrestricted semantic AI or nondeterministic classification.
Keep this rule-based and auditable.

7. EVIDENCE PROXIMITY
Measure how closely matched signals occur within source-page evidence.

Signals occurring together within the same relevant evidence region should
receive stronger support than signals scattered across unrelated pages.

The implementation must remain deterministic.

8. COMPETENCY SCORING
Replace the current simplistic:

distinct_signals * 2.0
+ page_count * 0.5

model with the hardened deterministic scoring model.

The scoring model must incorporate, as appropriate:

signal specificity
signal independence
phrase hierarchy collapse
negative-context filtering
evidence proximity
supporting pages

Keep the score explainable and auditable.

9. COMPETITOR DETECTION
A candidate must be evaluated against competing competencies.

Do not classify a competency as strong merely because it has one reasonable
signal when another competency has materially stronger evidence.

The output must retain enough information to explain competitor effects.

10. DETERMINISTIC THRESHOLDS
Thresholds must be explicit constants or an equivalent deterministic
configuration.

Do not use arbitrary implicit thresholds.

The same inputs must always produce identical candidate ordering,
scores and classifications.

11. CANDIDATE CLASSIFICATION
Classification must be deterministic.

Use the frozen contract's intended candidate/confidence model, but do not
silently invent business rules that conflict with the existing architecture.

Candidates remain candidates.

No automatic confirmation is permitted.

12. HUMAN REVIEW REQUIRED
Every generated candidate must explicitly contain:

human_review_required: true

Every source must also remain subject to human review.

No generated mapping may be marked confirmed.
